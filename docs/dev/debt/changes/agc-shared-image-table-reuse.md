# libSceAgcDriver

## add Functional

- [Image table reuse across queue workers](../../../core/libs/prx/libSceAgcDriver/Graphics/src/ShaderResources.cpp) (libSceAgcDriver) - remembered image tables are shared by every thread, 16 at most. A reuse in another collect state collects the texels again by ranges joined per 64 KiB block, refused when the change log cannot tell the mapping changes or the depth-surface or multisample-claim serial moved. Memory is proved per range, entry by entry in one written since the last whole proof. Entries under a mapping change, a write or pending results when remembered, up to half the table, are looked up again alone; more resolve it whole or leave it unremembered, as do results pending over a kept entry at reuse. A storage-viewed entry keeps its view while its image is cached, no other image has results pending over it and memory matches; one first taken over pending results is kept after they are stored, where a lookup could view the surface's own cached image. Not measured in game.

## change [Multisampled target guest access]

- [Multisampled target guest access](../../../core/libs/prx/libSceAgcDriver/Graphics/src/MultisampleTarget.cpp) (libSceAgcDriver) - the memory a multisampled color target throws on (CPU read, index buffer read, fixed-function vertex buffer read, DMA copy, texture or storage image read) uses fragment-aware 64 KiB blocks for the RenderTarget, Z64KBX and D64KBX tile modes. [AMD Addrlib's GFX10 thin-block rule](https://github.com/GPUOpen-Drivers/pal/blob/c5e800072a32f68b6ccc4422936d96167c6e0728/src/core/imported/addrlib/src/core/addrlib2.cpp#L1680-L1712) gives the block width and height from element bytes and fragment count; its [surface-size calculation](https://github.com/GPUOpen-Drivers/pal/blob/c5e800072a32f68b6ccc4422936d96167c6e0728/src/core/imported/addrlib/src/gfx10/gfx10addrlib.cpp#L4000-L4005) rounds both extents to those blocks and multiplies by element bytes and fragments. Thus a 1920x1080 4x RGBA8 surface occupies 0x1fe0000 bytes, leaving the next allocation at +0x2000000 outside the guard. The 2x and 8x block orientations differ from treating the fragments as a larger element. Console address-layout equivalence has not been measured. Other tile modes retain the conservative `max(CB bytes * samples, width * height * element bytes * samples)` bound, which may still reject a distinct allocation. Live targets remain cached per device, surface address, format, extent and sample count. Retired cache owners are removed on the next target, sampled or storage lookup; outstanding recorded work and sampled views retain their images. Ordinary sampled and storage bindings check the color-target guard before resource reuse, including precollected sampled lookups. Reused image tables check multisample color-target registration only outside the collect epoch they were proved in; their per-element fault handling and native multisample sampling require a separate reuse proof.
