# libSceAgcDriver

## add Functional

- [Persistent compute pipeline binaries](../../../core/libs/prx/libSceAgcDriver/Graphics/src/PipelineBinaryStore.cpp) (libSceAgcDriver) - only compute pipelines of at least `APS5_PIPELINE_BINARY_MIN_WORDS` SPIR-V words whose build took at least `APS5_PIPELINE_BINARY_MIN_MS` are stored; graphics pipelines and smaller or faster compute pipelines use the driver pipeline cache alone. A capture build runs without the pipeline cache, so a stored pipeline is not in the cache file. Device state enters the key only through the driver's global key; the per-pipeline key is left out (NVIDIA 620.73.04 returns a new one in each process). That driver also refuses some stored binaries in a later process (`VK_PIPELINE_COMPILE_REQUIRED`); those are rebuilt and captured again each time. Files over 256 MiB or with more than 64 binaries are not stored, and `driver/binaries/` has no eviction. Measured on NVIDIA 620.73.04 only; other drivers only through the CPU tests. Labels: gpu, tested, linux.
- [Register-preserving pipeline binary calls](../../../core/libs/prx/libSceAgcDriver/Graphics/src/PreservedCall.cpp) (libSceAgcDriver) - the NVIDIA proprietary driver's `vkGetPipelineKeyKHR(device, NULL, ...)` returns with the low 32 bits of `rbx` set to 1 (620.73.04, Linux: every call of 200; the other pipeline binary entry points changed no register in 200 calls); #18082 reports `rdi` on Windows. Every pipeline binary call saves and restores the callee-saved registers, MXCSR and the x87 control word; it cannot undo a driver write outside the driver's own frame. The Win64 body ran only under Wine, not on Windows with an NVIDIA driver. Platforms other than x86-64 Linux and Windows have no such call, so there the NVIDIA proprietary driver keeps binaries off unless `APS5_UNSAFE_PIPELINE_BINARIES=1`. Closes when: NVIDIA ships a driver whose global key query preserves the callee-saved registers. Labels: gpu, tested, linux, windows.
